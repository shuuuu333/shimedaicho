# 締め台帳 これからの計画

最終更新: 2026-09-15

**これが入口の文書。** 作る・配る・知ってもらう の 3 つを 1 枚にまとめた。
機能ごとの細かい経緯は [レジ計画](レジ計画.md) と [進捗](進捗.md) にある。

目的は 1 つ。**自分以外の店が、自分で見つけて、自分で入れて、使い続けること。**
いま足りないのは機能ではない。使っている店が 0 軒であること。

---

## いまどこにいるか

| | できていること | 残っていること |
|---|---|---|
| **作る** | 日報・締め・給料・シフト・キャスト・レジ・領収書・LINE 通知・オフライン・同期・お試しデータ・はじめの設定。テスト 270 件 | 実店舗で 1 週間／2 台の実地テスト／SQL の手作業 2 件／P2（コンカフェ） |
| **配る** | PWA を公開（ホーム画面に追加で使える）・紹介ページ・カード画像 | **App Store**（未）・Google Play（後回し） |
| **知ってもらう** | X（@kojinkaihatu）・紹介ページ・意見フォーム | TikTok（未）・Shorts（未）・**使っている店 0 軒** |

作る所はもう足りている。**これ以上作っても、使う人は増えない。**
ここから先は「配る」と「知ってもらう」に時間を使う。

---

## 決めたこと

1. **App Store に出す。** 年 99 ドルを払う。理由は下に書く
2. **Google Play は後。** いま個人のアカウントは、本番に出す前に
   **12 人のテスターで 14 日間**のクローズドテストが要る。12 人がいない
3. **アプリ本体に計測を入れない。** 店の金を扱うアプリで計測は嫌われる。
   審査で申告する項目も増える。数は紹介ページ側だけで見る
4. **無料で出す。** 課金を入れると審査の項目が増え、Apple に 15〜30% を渡す話になる。
   使う店が増えてから考える

## ① 配る — App Store に出す

### なぜ PWA のままでは足りないか

PWA は「URL を送って、ホーム画面に追加してもらう」形になる。
これは**人に勧めてもらうときに必ず 1 手詰まる**。
「App Store で 締め台帳 って調べて」で終わるのとは、渡しやすさが違う。

検索に出ることも大きい。夜職の店長が「キャバクラ レジ」で App Store を探したとき、
そこに無いものは無いのと同じ。

### 審査で落ちる所と、その対策

ここが本番。**「ウェブサイトを包んだだけ」のアプリは落ちる**（規約 4.2）。
落ちないために、ブラウザにできないことを入れる。どれも作った方が使い勝手も上がる。

| | 入れるもの | 理由 |
|---|---|---|
| 🔴 | **印刷をネイティブに** | いまの領収書は `window.print()`（[Receipt.tsx:71](../src/ui/screens/Receipt.tsx)）。**iOS の WebView では動かない。**包んだ瞬間に領収書ボタンが無反応になる。ここは必ず直す |
| 🔴 | **アカウントの削除** | 規約 5.1.1(v)。作れるなら消せないといけない。いま「ログアウト」しかない（[CloudCard.tsx:51](../src/ui/components/CloudCard.tsx)）。設定に「アカウントを削除」と、サーバー側で行を消す関数が要る |
| 🟠 | **Face ID / Touch ID** | いまの PIN を生体認証に。レジを触る端末は人の手に渡る |
| 🟠 | **通知（端末の中だけ）** | 「締めがまだ」「明日の出勤」。サーバーなしで出せる |
| 🟠 | **共有シート** | 日報や領収書を LINE へそのまま渡す |
| 🟡 | **ファイルへ書き出し** | バックアップを「ファイル」アプリへ。いまはブラウザのダウンロード |
| 🟡 | **触覚（Taptic）** | ガラスのタブを触ったときに指に返る。ここまで作った手触りが本物になる |
| 🟡 | **同梱して起動** | 中身を端末に入れて配る。通信ゼロで開く |

包む道具は **Capacitor**（MIT）。約束どおり MIT / Apache-2.0 の部品しか入れない。
`src/domain/calc.ts` は触らない。**中身は今のまま、外側だけ足す。**

### その他に要るもの

| | 内容 |
|---|---|
| 審査メモ | 「ログインしなくても全部触れます」と書く。デモアカウントを渡さずに済む（規約 2.1） |
| 年齢制限 | 質問に正直に答える。酒の話が出るので 17+ になる見込み |
| プライバシー | 集めるのは「ログインする人のメールアドレス」だけ。追跡は無し → ATT の許可ダイアログは要らない |
| 輸出 | `ITSAppUsesNonExemptEncryption = false`（HTTPS だけ）。毎回の質問が消える |
| スクリーンショット | 6.9 インチを 1 組。**派手な絵は入れない。**レジ・日報・給料・シフト・領収書の 5 枚 |
| 名前と検索語 | 名前は「締め台帳」。検索語に キャバクラ / ガールズバー / レジ / 日報 / 締め / 給料計算 / バック / シフト / 夜職 |
| 出す人の名義 | 個人で登録すると、**販売者の名前として本名が出る**。ここは登録の前に必ず確かめる。気になるなら屋号（法人・個人事業）での登録を調べる |

## ② 知ってもらう — 毎週のリズム

### 誰に言うか

順番がある。

1. **黒服・スタッフ**（締めを実際にやらされている人）… いちばん痛い
2. **店長・オーナー**（金を決める人）… 入れるかを決める
3. **キャスト**（自分の給料が見たい人）… 店に「入れて」と言わせられる

3 番を軽く見ない。**キャストが欲しがると、店が入れる。**
自分の出勤・バック・未払いが手元で見えるアプリは、店から見ても嫌がられにくい。

### 言うこと

機能の話をしない。**痛い所から入る。**

> 「閉店後、紙と電卓で 2 時間」 → 「打った瞬間に終わってる」

### 撮り方の決まり

- **手元だけ。**顔・店名・客・キャストは映さない
- 10〜20 秒。頭の 2 秒で「紙と電卓」を見せる
- 週 3 本。毎日は続かない。**当たった 1 本を伸ばす方が効く**

### 出す先

| | 役割 |
|---|---|
| **TikTok** | 本命。夜職の人がいちばんいる |
| **Instagram リール** | 同じ動画をそのまま出す。作る手間は増えない |
| **X（@kojinkaihatu）** | 作っている過程。個人開発の人が見ている。店は来ないが、応援と紹介が来る |
| **YouTube Shorts** | 残る場所。後から「キャバクラ レジ」で掘られる |

### 台本 10 本（機能がそのままネタ）

| | 見せるもの | 一言 |
|---|---|---|
| 1 | 紙・電卓 → レジを打つ | 「これ、もうやらなくていい」 |
| 2 | 現金が合わない夜 | 「どこで合わなくなったか、アプリが候補を出す」 |
| 3 | バック単価・売上% の上限 | 「給料の計算、もう手でやらない」 |
| 4 | カード手数料 | 「お客様からもらう設定、1 か所で終わり」 |
| 5 | 先週のシフトを写す | 「来月ぶん、3 秒」 |
| 6 | LINE に日報が飛ぶ | 「店にいなくても today が分かる」 |
| 7 | 打ち忘れの検知 | 「入店したまま帰った卓、教えてくれる」 |
| 8 | 今月の着地予測 | 「このままだと今月いくらか」 |
| 9 | お客様に見せる明細 | 「誰に何本ついたかは、客には見せない」 |
| 10 | キャスト画面 | 「自分の給料、自分で見れる」← **キャスト向けに単体で出す** |

### 見る数字

いいねを見ない。**次の 3 つだけ。**

1. TikTok の**保存数**（「後でやる」＝本気）
2. プロフィールのリンクの**クリック数**
3. **意見フォームの回答数**（1 件でも来たら、その日は勝ち）

紹介ページ側だけ、Cookie を使わないカウンタ（Cloudflare Web Analytics など）を後で足してもいい。
**アプリ本体には入れない。**

## やらないこと

| | 理由 |
|---|---|
| 広告を出す | 誰に当たるか分からないうちに金を燃やす |
| 課金を今つける | 使っている店が 0 軒。値段を決める材料が無い |
| P2 を先に作る | 想像で作ることになる |
| アプリに計測を入れる | 店の金を扱うアプリで嫌われる。審査の申告も増える |
| 顔を出して撮る | 夜職は身元が割れると困る人がいる。手元で足りる |
