## [A] ✅ キャストに台帳を丸ごと見せるのをやめる

### なぜ要るか

いまの本番は、**QR で入ったキャストのトークンがあれば台帳 JSON を丸ごと読める。**
全員の時給・給料・未払い、店の売上・利益・手元現金・経費まで入っている。
アプリの画面では隠しているが、**隠しているだけで、届いてはいる。**

キャスト用アプリを App Store に単体で出すなら、ここは先に閉じる。
他人の給料が入った通信をするアプリは、配れない。

### 手順

1. https://supabase.com/dashboard で自分のプロジェクトを開く
2. 左の **SQL Editor** → **New query**
3. `supabase/patches/1f-cast-ledger.sql` の中身を**全部**貼る
4. **Run**（⌘Return）

**何度実行しても安全。**「もう実行したか分からない」ときは、もう一度流していい。

### 実行したあとの確認

同じ SQL Editor に貼って Run する。

```sql
select '関数 my_member' as 確認, count(*)::text as 結果
  from pg_proc where proname = 'my_member'
union all
select '関数 my_cast_ledger', count(*)::text
  from pg_proc where proname = 'my_cast_ledger'
union all
select '列 cast_id / can_register', count(*)::text
  from information_schema.columns
 where table_name = 'shop_members' and column_name in ('cast_id', 'can_register')
union all
select 'ledgers_select の条件', pg_get_expr(polqual, polrelid)
  from pg_policy
 where polrelid = 'public.ledgers'::regclass and polname = 'ledgers_select';
```

こう出れば通っている。

| 確認 | 出るはずの結果 |
|---|---|
| 関数 my_member | `1` |
| 関数 my_cast_ledger | `1` |
| 列 cast_id / can_register | `2` |
| ledgers_select の条件 | `(my_role(shop_id) = ANY (ARRAY['owner'::text, 'staff'::text]))` |

いちばん下が `is_member(shop_id)` のままなら、**流せていない。**

### 壊れないか

壊れない。アプリ側は「関数がまだ無い環境では今までの経路に落ちる」形で書いてある
（`src/data/cloud.ts` の `myMember` / `pullCastLedger` が `error` のとき `null` を返す）。
**先に SQL を流しても、先にアプリを出しても、どちらの順でも動く。**

流したあと、キャストのアカウントで入って「シフト」と自分の給料が今まで通り見えるかだけ見る。
見えなければ `shop_members` のその人の行に `cast_id` が入っていない
（QR 招待より前に手で足したメンバー）。設定 → クラウド同期 → メンバー から選び直す。

## [B] ✅ LINE の中継を入れ直す

### なぜ要るか

いま本番に載っている版は**オーナーしか送れない。**
`supabase/functions/line-notify/index.ts` は直してあって、**スタッフも送れる**。
貼り直していないので効いていない。

営業中の通知は「オーナーが店にいないとき」に値打ちが出る。
カウンターに立っているスタッフの端末から送れないと、ほぼ意味がない。

### 手順

1. https://supabase.com/dashboard → **Edge Functions**
2. 一覧の **line-notify** を開く
3. コードの画面にして、**中身を全部消して**
   `supabase/functions/line-notify/index.ts` を**全部**貼る
4. **Deploy**

### 確認

- Edge Functions の一覧で、**line-notify の更新時刻が今になっている**
- スタッフの役割のアカウントでアプリに入り、日報から LINE の通知を送る
  → 届けば通っている。`この店のオーナーとスタッフだけが送れます` が出るなら**古いまま**
- 送れないときは Edge Functions の **Logs** を見る

### 鍵の置き場所（変えない）

チャネルアクセストークンは **Supabase の Secrets にだけ**置く。

| 名前 | 中身 |
|---|---|
| `LINE_CHANNEL_TOKEN` | Messaging API の長期トークン |
| `LINE_TO` | 送り先の LINE ユーザー ID（空なら友だち全員へ） |

**このアプリには入れない。**持っていれば誰でもその公式アカウントとして送れてしまう。
`.env.local` にも置かない。

## [C] ✅ シフト希望のテーブル

### なぜ要るか

台帳（`ledgers`）は owner/staff しか書けない。[A] でそう決めたばかりで、
ここを開けるわけにはいかない（台帳は 1 つの JSON なので、開けたら店の売上まで書ける）。

キャストが「来月ここ入れます」を出すには、**本人が書ける置き場**が要る。
それが `shift_wishes` と `shift_wish_done`。

**流すまでは、店（オーナー・スタッフ）の画面だけで動く。**
希望を店が代わりに書き留める形なら、いまのままで使える。
キャスト端末から出せるようになるのは、これを流して同期をつないでから。

### 手順

1. SQL Editor → New query
2. `supabase/patches/2-shift-wishes.sql` を全部貼る
3. Run

### 確認

```sql
select table_name from information_schema.tables
 where table_schema = 'public' and table_name in ('shift_wishes', 'shift_wish_done');
```

2 行返れば作れている。**2026-09-15 に実行済み**（テーブル 2・関数 1・ポリシー 4 の計 7 件を確認）。
