## 7. 伝票のリアルタイム同期（P3）

複数端末で席を共有する。1-e（キャストが卓で会計する）に必須。

| | 内容 | ファイル |
|---|---|---|
| ✅ | 1. `check_ops` のテーブルと RLS（追記だけ・キャストは読めない） | `supabase/schema.sql` |
| ✅ | 2. ops を畳んで `Check` を作る純粋関数 | `src/domain/checkOps.ts` |
| ✅ | 3. 送信待ちの列・再送・冪等 | `src/state/opsSync.ts` |
| ✅ | 4. Realtime 購読と画面への反映 | 同上 |
| ✅ | 5. 「未送信◯件」の表示 | `src/ui/screens/Register.tsx` |
| ⬜ | 6. **2台での実地テスト**（同時に同じ卓、片方を機内モード）← 実機が必要 |

**競合の決まりは「順に畳めば出てくる」形にした**（特別扱いを書いていない）:
注文・延長は両方残る／会計は開いているときだけ効く＝同時に押しても先の1回／
同じ行の数量は後勝ち／取消は最初の理由が残る。

### 席の移動・伝票の合算と分割

卓を移る、2組が合流する、割り勘で分ける。どれもまだできない。
ops の形になったので、「移す」「まとめる」「分ける」も操作として足せるようになった。

## 検証

```bash
cd ~/Desktop/shimedaicho
npm test          # 184 件
npx tsc -b
npm run build
```

ブラウザは `.claude/launch.json` の `shimedaicho` を `preview_start` で起動する。
`npm --prefix ... run dev` は preview 内で固まるので使わない。
Browser pane では click がタイムアウトすることがあるので、JS から MessageChannel の
tick で待つやり方が確実。

### 変えない約束

`src/domain/calc.ts` の給与・締めの計算は、旧コードとの同値テスト 300 件が守っている。
バック単価の引数を足した以外は触っていない。
