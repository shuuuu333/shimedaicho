# 締め台帳 再構築計画

## Context

現行の「締め台帳」は claude.ai のアーティファクト 1 ファイル（HTML 1,683 行）で動いているキャバクラ向け締め台帳アプリ。
画面は 今月 / 日報 / キャスト / 設定 の 4 つ。保存はアーティファクトの `data/store.json` への publish と localStorage の二重持ち。
コードは全て読了済み（`~/.claude/projects/-Users-saitoushuntarou-Desktop/e250ad5d-.../tool-results/artifact-6e69dba9-1788304021-b1e4.html`）。

ユーザーの困りごと（本人回答）:
- **入力が面倒・分かりにくい** — 日報が 1 ページ縦長で、キャストごとにアコーディオンを開いて時間・本数・控除・日払いを入れる構造。
- **データの保存・共有が不安** — 「この端末のみ」と「クラウド保存」が状況で切り替わり、どこに何が残っているか見えない。

決定事項:
- 成果物は **アプリの再構築がメイン**。要件定義書は軽めに 1 本添える。
- Desktop に **ローカルプロジェクト** として作る（将来の公開・課金を見据える）。
- 保存は **まず端末内（IndexedDB）のみ**。同期層はあとから Supabase を差し込める構造にしておく。
- Node.js を Homebrew で入れてよい → **Vite + React + TypeScript + PWA**。

## 成果物

1. `/Users/saitoushuntarou/Desktop/shimedaicho/` — 新アプリ（git 管理）
2. `shimedaicho/docs/要件定義書.md` — 現状の課題・目的・機能要件・画面構成・データモデル・ロードマップ（Phase1 端末内 → Phase2 Supabase 同期 → Phase3 公開/課金）

## 実装ステップ

### 0. 環境
- `brew install node` → `npm create vite@latest shimedaicho -- --template react-ts`
- 依存: `dexie zustand vite-plugin-pwa`、dev: `vitest @testing-library/react jsdom`
- `git init`、最初のコミット。

### 1. 要件定義書（軽め）
現行コードから読み取った仕様を正として書く。
- 用語: 在籍キャスト / 派遣 / バック（件数・売上%） / 日払い / 精算 / まとめ日払い / 実査現金
- 計算式: 時給×丸め時間 ＋ バック − 控除、派遣は保証日給ベース、現金残 = 起点 + 現金売上 − 現金経費 − 支払い − 銀行入金、カード未回収 = カード売上×(1−手数料) − 入金
- 変える点 / 変えない点 / 後回し（Supabase・ログイン・複数店舗）

### 2. 計算ロジック移植（`src/domain`）
現行 §3 の関数を型付きで移植: `shiftMinutes` `payOf` `dispatchPay` `dayTotals` `monthTotals` `castMonth` `dispatchMonth` `balances` `cashAsOf` `settlementsFor` `owedList`。
`migrate.ts` は現行 v2 JSON（`{v:2, shop, backItems, casts, days}`）を **無損失** で新スキーマへ。
`calc.test.ts` で `test/legacy-calc.js` と同一入力→同一出力の同値テスト（ランダム生成した状態 200 件 ＋ 手書きケース）。

### 3. 保存層（`src/data`）
- `repository.ts`: `load() / save(state) / subscribe(cb) / snapshots()` のインターフェース。Phase2 で `supabaseRepository.ts` を追加できる形。
- `localRepository.ts`: Dexie。テーブル `state`（単一ドキュメント）＋ `snapshots`（日時・サイズ・JSON）。
- `backup.ts`: JSON 書き出し（Web Share API → 無ければダウンロード）、JSON 読み込み（現行の `締め台帳_バックアップ_*.json` と `store.json` の両方を受け付ける）、月次 CSV（現行と同じ列）。
- 保存インジケータは「保存済み HH:MM」「最終バックアップ N 日前」を常時表示。

### 4. 画面（`src/ui`）— 入力の負担を減らす
**日報を「締めウィザード」に変える**（一番の変更点）:
1. 売上（現金・カード・客数）
2. 出勤 — キャスト名をチップで並べ、タップで出勤 ON。選んだ子だけ下に並ぶ。行タップで **ボトムシート** に時間・バック本数・控除・日払い。出退勤は設定の初期値が自動、「遅刻 +30分」「早退 −30分」ボタン。
3. 派遣
4. 経費
5. 現金・入金（銀行入金・カード入金・実査）→ 末尾に「この日の差引」まとめ
- 上部にステップ進捗、各ステップは 1 画面に収める。どのステップからでも入れる。
- 「前回の出勤をコピー」「未入力の日」チップ、6 秒 Undo は現行どおり維持。
- `NumberField`: inputmode=numeric、桁区切り表示、¥ 表示、クリアボタン、全角数字を半角に正規化。

**今月 / キャスト / 設定** は現行の情報設計を維持して移植（SVG グラフ・カレンダー・精算「今日精算」含む）。

### 5. 移行
設定画面に「以前の締め台帳から読み込む」を置き、現行アプリの「全データのバックアップ」JSON を取り込む。ユーザーには現行アーティファクトでバックアップ JSON を 1 度書き出してもらう。

## 検証

- `npm test` — 計算の同値テストが全通過
- `npm run dev` → Claude Browser（mobile 375px）で: 設定 → キャスト登録 → 日報ウィザード 5 ステップ → 今月に反映 → 精算 → リロードしてデータが残る → JSON 書き出し/読み込みで往復一致
- 現行アーティファクトの JSON を取り込んで、今月の営業利益・未払い・手元現金が現行画面と一致することを目視
- `npm run build && npm run preview` で PWA インストール可能、オフラインで起動
