# 締め台帳 再構築 要件定義書

作成日: 2026-09-02　対象: キャバクラ 1 店舗の締め（売上・給料・現金）を毎日記録するアプリ

## 1. 背景と目的

現行版は claude.ai のアーティファクト（HTML 1 ファイル）で動いている。毎日の締めには使えているが、次の 2 点が負担になっている。

| 困りごと | 現行の原因 |
|---|---|
| 入力が面倒・分かりにくい | 日報が 1 ページ縦長。キャストごとにアコーディオンを開き、時間・本数・控除・日払いを探して入れる。どこまで入れたか分からない |
| データの保存・共有が不安 | 「クラウド保存」と「この端末のみ」が状況で切り替わり、どこに何が残っているか見えない。バックアップの習慣もつきにくい |

再構築の目的:

1. **締めを 5 ステップの決まった手順にして、3 分で終わらせる**
2. **保存先を 1 つ（端末内データベース）にし、保存状態・バックアップ状況を常に見せる**
3. 将来の複数端末同期・スタッフ共有・他店提供に進める土台（ローカルプロジェクト、型付きのデータモデル、保存層の分離）を作る

## 2. 利用者と場面

- 利用者: 店のオーナー／店長 1 名（将来はスタッフ数名）
- 場面: 閉店後、スマホで 3 分。翌日以降に月次の確認、給料日に精算
- 端末: iPhone / Android のブラウザ（ホーム画面に追加して使う）。PC でも同じ画面

## 3. 用語

| 用語 | 意味 |
|---|---|
| 在籍キャスト | 店に登録している女の子。時給制 ＋ バック |
| 派遣 | その日だけ来る子。日給（保証額）＋ 派遣単価のバック。登録不要、名前で自動集計 |
| バック | 成果給。「件数」型（単価×本数）と「売上%」型（対象売上×％）がある |
| 日払い | その日に手渡した給料。残りは未払いとして溜まる |
| 精算 | 溜まった未払いを渡すこと。人件費は増えず、手元の現金だけ減る |
| まとめ日払い | 誰にいくらか分けずに払った日払い。人件費に入るが個人には紐づかない |
| 実査現金 | 金庫＋レジを実際に数えた額。計算上の現金残との差を見る |

## 4. 計算ルール（現行を踏襲。変更なし）

- 出勤時間 = 退勤 − 出勤（日跨ぎ対応）− 休憩。設定の丸め（15 分など）で切り捨て
- 在籍の支給額 = floor(時間 × 時給) ＋ バック − 控除。時給は個別 → 無ければ店の基本時給
- 派遣の支給額 = 日給（未入力なら店の基本日給）＋ 派遣単価のバック − 控除
- バック（件数）= floor(単価 × 本数)、バック（売上%）= floor(対象売上 × ％ ÷ 100)
- 未払い = 支給額 − 日払い − 精算
- 日の人件費 = 在籍 ＋ 派遣 ＋ まとめ日払い
- 日の差引 = 売上 − 人件費 − 経費 − カード手数料（カード売上 × 率）
- 月の営業利益 = 売上 − （人件費 ＋ 固定人件費）− （経費 ＋ 固定費 ＋ カード手数料）
- 手元の現金 = 起点の現金 ＋ Σ（現金売上 − 現金経費 − 日払い・精算・まとめ − 銀行入金）
- カード未回収 = Σ（カード売上 × (1 − 手数料率) − カード会社からの入金）
- 年の集計 = 各月の合計。固定人件費・固定費は **日報のある月だけ** 引く（休業月に固定費を積まない）

旧コードの計算部を `test/legacy-calc.js` に切り出し、新実装がランダム 300 通りの状態で同じ答えを出すことをテストで保証する。
（旧コードの月集計にあった「精算払いの合計が NaN になる」バグは新実装で 0 始まりに直した）

## 5. 機能要件

### 5.1 変える（今回の主眼）

| # | 要件 |
|---|---|
| F1 | 日報を **5 ステップのウィザード** にする: ①売上 ②出勤 ③派遣 ④経費 ⑤締め（現金・入金・精算・差引）。上部に進捗、各ステップは 1 画面。どのステップからでも入れる |
| F2 | 出勤は **キャスト名のチップをタップ** で ON/OFF。ON の子だけ下に並び、行をタップすると **ボトムシート** で時間・本数・控除・日払いを入れる |
| F3 | 出退勤は設定の初期値が自動で入る。「遅刻 +30/+60」「早退 −30/−60」「定時に戻す」ボタン |
| F4 | 数値入力は専用部品: 数字キーボード、桁区切り表示、クリアボタン、全角数字・カンマ・¥ を吸収 |
| F5 | 未入力の状態が分かる: 出勤行に「本数未入力」、上部に売上・人件費・差引のライブ表示 |
| F6 | 保存は **端末内データベース（IndexedDB）** に自動保存。右上に「保存済み HH:MM」を常時表示 |
| F7 | **保存の履歴**（10 分おき・取り込み前に自動、直近 30 世代）から任意の状態に戻せる |
| F8 | **バックアップ JSON の書き出し／読み込み**。旧版（claude.ai 版）のバックアップもそのまま読める。最後のバックアップ日を表示し、30 日超で注意 |
| F9 | 日報を開いただけでは記録を作らない（最初の入力で作る）。「入力済み ○日」が実態と合う |
| F10 | **派遣の支払いを派遣ステップに直接置く**（第 2 回）。各行に支払額と「全額払う」ボタン、全額払えば「全額払い済み」。ステップ下に「今日払った額／未払い」 |
| F11 | **円グラフ**（第 2 回）。「売上の使われ方」カードで 棒／円／キャスト別の売上貢献／曜日別 を切り替える。キャスト別は売上%型バックの対象売上（無ければバック額）で見る |
| F12 | **年表示**（第 2 回）。今月画面の「月／年」切替。1〜12 月の売上（現金／カード）と利益の折れ線、月別の表、年の使われ方 |

### 5.2 変えない（現行どおり移植）

- 今月: 営業利益・人件費率・客単価・前月比、未払い／手元現金／カード未回収／経費のタイル、日別売上グラフ／カレンダー、売上の使われ方、キャスト別給料、日別明細、CSV
- キャスト: 月別の給料表・明細・バック内訳・派遣の表・未払いの精算（今日精算／全員まとめて）・在籍の登録
- 設定: 店舗（時給・丸め・初期時刻・派遣日給・手数料）・バック単価・現金の起点・固定費
- 削除は即実行 ＋ 6 秒の「元に戻す」
- ライト／ダーク両対応、スマホ幅優先（最大 480px）

### 5.3 後回し（Phase 2 以降）

- クラウド同期（Supabase）、ログイン、スタッフ招待・権限
- 複数店舗、課金、公開配布
- 顧客管理・ボトルキープ・シフト予定

## 6. 非機能要件

- オフラインで起動・入力できる（PWA、Service Worker でキャッシュ）
- 入力から 300ms 以内に保存。画面を閉じるときにも保存を試みる
- データはブラウザのプロファイル内に留まる。外部送信なし（Phase 1）
- 1 年分（365 日 × 20 名）でも各画面が 100ms 以内に描画できること

## 7. 画面構成

```
下タブ: 今月 ／ 日報 ／ キャスト ／ 設定
日報:  [日付バー] [1.売上 2.出勤 3.派遣 4.経費 5.締め] [売上・人件費・差引]
       ステップ本体 → [戻る][次へ]   ボトムシート（キャスト／派遣の明細）
```

## 8. データモデル（v3）

```
Ledger { v:3, shop, backItems[], casts[], days{ "YYYY-MM-DD": DayRecord } }
Shop   { name, cardFeeRate, openingCash, openingDate, defaultWage, roundMinutes,
         fixedLabor, fixedCost, dispatchGuarantee, openTime, closeTime }
BackItem { id, name, type:"count"|"amount", rate, rateD }
Cast   { id, name, wage|null, active }
DayRecord { cashSales, cardSales, guests, expenses[], bankDeposit, cardReceived,
            cashCounted, payout, shifts{castId: Shift}, dispatch[], settle[] }
Shift  { on, in, out, breakMin, backs{backId: qty}, deduct, paid }
DispatchRow { id, name, guarantee|null, in, out, breakMin, backs, deduct, paid }
Expense { id, name, amount, method:"cash"|"card"|"bank" }
Settlement { id, who:"c:<castId>"|"d:<名前>", forMonth:"YYYY-MM", amount }
```

数値は `number | null`（null = 未入力）。旧版の文字列は `migrate()` で無損失に変換する。

## 9. 技術構成

Vite + React + TypeScript、zustand（状態）、immer（不変更新）、Dexie（IndexedDB）、vite-plugin-pwa、vitest。
保存層は `Repository` インターフェースで分離し、Phase 2 で `SupabaseRepository` を追加する。

```
src/domain   型・計算・移行（UI に依存しない）
src/data     保存層（IndexedDB）・バックアップ
src/state    zustand ストア
src/ui       画面と部品
test/        旧コードのオラクル
```
