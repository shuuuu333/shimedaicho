## スマホアプリとして入れられるようにする（2026-09-04）

## 現金の照合を分かるようにする（2026-09-04）

「実際に数えた現金を入れたあと、まとめ日払いを入れると数字が合わない」との指摘を検算した。
**計算そのものは正しかった**（現金売上30,000 − まとめ19,200 = 10,800、実査12,500 なら 過剰1,700）。
分かりにくかったのは、実査の欄が支払いの欄より **上** にあり、あとから支払いを入れると
上の判定だけが黙って変わる作りだったこと。

- 実査を **締めステップの最後**（すべての支払いを入れ終えたあと）に移した
- 「現金の照合」カードに内訳を全部出す: 前の日までの残り ＋ 現金売上 − 現金経費 − 給料で払った額 − 銀行入金 ＝ 計算上の残り
- 差があるときは「足りない／多い」と、数えた額と計算上の額を並べて示し、確かめる場所を案内する
- 設定「現金の起点」で日付欄と金額欄が重なっていたのを、`DateField`（時刻と同じくOSのピッカーを透明に重ねる）と縦並びで解消

## QRだけでログインできるようにする（2026-09-04）

「案内を送る」（LINE用の文をコピーする機能）を削除し、代わりに **QRを見せるだけで店に入れる** 形にした。
メールもパスワードもいらない。

**しくみ**
- オーナーが 設定 → クラウド同期 → メンバー →「QRで招待」で、役割（スタッフ／キャスト）を選んで QR を出す
- 相手がスマホのカメラで読むと `?join=<token>` でアプリが開き、**匿名でログイン**してから `redeem_invite` を呼ぶ
- 招待は **30分で失効・1回だけ**。使うと `used_at` が入り、二度と使えない

**DB（`supabase/schema.sql`）**
- `shop_members` に `user_id` と `name` を追加。`is_member` はメール一致か本人一致で判定する
- `shop_invites` テーブル（token・役割・名前・cast_id・期限・使用済み）。閲覧と発行はオーナーのみ
- `redeem_invite(token)` は `security definer` の関数。まだメンバーでない人でも自分を加えられる。
  返り値は `json`（`returns table` だと出力名と列名がぶつかってエラーになった）
- Supabase の Authentication で **匿名サインインを有効化**

**注意点**
- QR そのものが鍵になる。人に見られると入られるので、30分の期限を短くしてある
- 匿名アカウントなので、その端末のブラウザデータを消すと入り直しになる（QRを出し直す）

```bash
npm install        # 初回のみ
npm run dev        # http://localhost:5173
npm test           # 計算の同値テストなど
npm run build      # 本番ビルド（dist/）
```

Claude Code のブラウザで見る場合は Desktop の `.claude/launch.json` の `shimedaicho` を使う（vite.js を node で直接起動する設定。`npm --prefix` 経由だと固まる）。
